# ESP32 ETH01 Power controller

Контроллер на WT32-ETH01 (ESP32 + LAN8720), который управляет питанием домашнего сервера
по состоянию сети в квартире. Сервер стоит на ИБП: когда питание квартиры пропадает, контроллер
штатно выключает сервер, а когда питание возвращается – включает его через Wake-on-LAN.

## Возможности

- Только Ethernet (DHCP, имя `esp32-eth01`). Wi-Fi и Bluetooth в прошивку не собираются.
- Проверка доступности сервера каждые N секунд: ICMP ping и HTTP `GET /ping`. Сервер считается
  онлайн, если ответила любая из проверок.
- **Питание пропало** (IO35 HIGH дольше заданного времени) – серверу отправляется HTTP-команда
  выключения, контроллер ждёт, пока сервер станет недоступен, при необходимости повторяет команду.
- **Питание появилось** (IO35 LOW дольше заданного времени) – Wake-on-LAN (3 magic packet),
  ожидание, пока сервер станет доступен, повторы.
- **Кнопка IO36** (удержание 4 с) – перезапуск сервера: выключение, затем включение.
- **Выходы IO32/IO33** – переключаются в LOW, когда питания нет дольше заданного времени, и в HIGH,
  когда питание есть. Отключаемо, в выключенном состоянии выходы всегда HIGH.
- Веб-интерфейс на одной странице: состояние, сценарии, настройки с автосохранением во flash.
- Пароль на веб-интерфейс, сброс перемычкой IO2–GND.
- Обновление прошивки по сети из веб-интерфейса, с автооткатом неработающей версии.

## Подключение

| Вывод | Назначение |
|---|---|
| IO35 | Наличие питания квартиры: HIGH – нет, LOW – есть (вход без подтяжки, нужна внешняя) |
| IO36 | Кнопка перезапуска, активный HIGH (вход без подтяжки, нужна внешняя) |
| IO32, IO33 | Выходы, HIGH – включено |
| IO2 | Сброс пароля: перемычка на GND при включении. Подтянут к питанию внутри, больше ничего к нему не подключайте |
| IO12 / IO14 / IO15 | Светодиоды красный / зелёный / синий, горят при LOW. IO12 – strapping-пин: схема не должна тянуть его вверх при старте |

Светодиоды: синий – удерживается кнопка; вспышки зелёного – идёт включение, вспышки красного –
идёт выключение; зелёный горит – сервер онлайн; красный горит – сервер недоступен;
красный мигает – нет сети.

## Веб-интерфейс

`http://<IP контроллера>/`

- **Пароль.** При первом входе страница просит задать пароль (не короче 6 символов). В flash
  хранится только его хэш (PBKDF2-SHA256 с солью). Вход действует до перезагрузки контроллера или
  часа бездействия (открытая страница опрашивает контроллер и продлевает вход), кнопка «Выйти»
  завершает сессию. После 5 неверных паролей подряд вход
  блокируется на 30 с.
- **Сброс пароля.** Замкните IO2 на GND и включите (или перезагрузите) контроллер: пароль
  удалится, страница попросит задать новый. Настройки при этом не сбрасываются. Снимите
  перемычку – иначе пароль будет сбрасываться при каждом включении.

| Настройка | По умолчанию |
|---|---|
| IP / HTTP-порт сервера | 192.168.1.200 / 8080 |
| MAC сервера для WOL / UDP-порт | AA:BB:CC:DD:EE:FF / 9 |
| HTTP-путь проверки (пусто – только ICMP) | `/ping` |
| HTTP-путь выключения | `/poweroff` (с ключом агента — `/poweroff?key=<ключ>`) |
| Подтверждение пропадания / появления питания | 600 / 60 с |
| Интервал проверки сервера | 10 с |
| Ожидание выключения / включения после команды | 60 / 60 с |
| Попыток отправки команды | 3 |
| Выходы IO32/IO33: выключение / включение | управление выключено, по 60 с |

Ожидание и число попыток общие для автоматики и кнопки. `GET /status` отдаёт состояние в JSON
(после входа).

## Сборка и прошивка

ESP-IDF 5.5.5. Flash 4 МБ, два слота прошивки по 1,7 МБ (таблица разделов `two OTA large`).

```bash
idf.py build
idf.py -p COM7 flash monitor
```

У WT32-ETH01 нет автоматического входа в загрузчик: перед прошивкой замкните IO0 на GND и
сделайте сброс. Исходники подключаются через `SRC_DIRS`, поэтому после добавления нового `.c`-файла
нужен `idf.py reconfigure`. Свои настройки menuconfig сохраняйте в `sdkconfig.defaults`
(`idf.py save-defconfig`) – `sdkconfig` в git не хранится.

Версия 1.1.0 меняет разметку flash (было 2 МБ и один слот), поэтому её **первый раз нужно
прошить по USB**. Сохранённые настройки переживут смену разметки (раздел настроек остаётся на
прежнем месте), при первом входе страница попросит задать пароль.

```
main/include/   заголовки        main/src/   исходники        main/web/index.html   страница
server/         агент для Proxmox и эмулятор сервера для проверки на Windows
firmware/       готовая прошивка текущей версии
```

## Готовая прошивка

В `firmware/` лежит собранная прошивка текущей версии (версия – в `firmware/VERSION`), чтобы
прошить контроллер без сборки.

- **По сети:** файл `firmware/esp32_eth01_controller.bin` (см. следующий раздел).
- **По USB** (IO0 на GND и сброс), из терминала ESP-IDF в папке `firmware/`:

  ```bash
  python -m esptool --chip esp32 -p COM7 -b 460800 write_flash @flash_args
  ```

  Адреса записи – в `firmware/flash_args`: `0x1000` bootloader, `0x8000` таблица разделов,
  `0xf000` ota_data_initial, `0x20000` прошивка (их же можно указать в веб-прошивальщике
  esptool-js). Раздел настроек (`0x9000`) не затрагивается, настройки и пароль сохраняются.

Папка обновляется сама: каждая успешная сборка копирует в неё файлы из `build/` и записывает
версию (`firmware/update.cmake`). Поэтому после промежуточных сборок git покажет изменённые
`.bin` – коммитьте их вместе с версией, которую проверили, иначе верните: `git restore firmware`.

## Обновление прошивки по сети

1. Задайте версию в `CMakeLists.txt` (`PROJECT_VER`) и соберите: `idf.py build`.
2. В веб-интерфейсе, карточка «Прошивка»: выберите `build/esp32_eth01_controller.bin` (или
   `firmware/esp32_eth01_controller.bin`), ещё раз введите пароль и нажмите «Обновить прошивку».
3. Контроллер проверит образ (тот же проект, контрольная сумма), запишет его в свободный слот и
   перезагрузится. Страница дождётся перезагрузки, загрузится заново и покажет, какая версия
   запустилась.

Версия не обязана расти: можно записать и более старую прошивку (начиная с 1.1.0 – в более ранних
нет обновления по сети). Чтобы отличить новую прошивку от откатившейся старой, страница сверяет
версию и время сборки.

Страница загружается заново после любой перезагрузки контроллера – обновления, сброса, включения
питания: новая прошивка может отдавать уже другую страницу.

Обновление недоступно, пока идёт сценарий автоматики и пока выходы IO32/IO33 выключены (после
перезагрузки они временно включились бы). Новая прошивка сама подтверждает работоспособность:
через 15 с после запуска, если получен IP и веб-интерфейс отвечает. Если она упала или не
подтвердилась, при следующей перезагрузке загрузчик вернёт предыдущую версию.

## Развёртывание на Proxmox

`server/power_server.py` – агент на сервере: `GET /ping` отвечает, пока система работает,
`GET /poweroff` выполняет `systemctl poweroff` (Proxmox сам останавливает ВМ и контейнеры).
Только стандартная библиотека Python 3.

От root на Proxmox:

```bash
mkdir -p /opt/power-server
cp power_server.py /opt/power-server/
cp power-server.service /etc/systemd/system/
```

`/etc/default/power-server`:

```
POWER_SERVER_ARGS="--port 8080 --allow <IP контроллера> --wol-interface eno1 --dry-run"
POWER_SERVER_TOKEN=<ключ: латиница, цифры, - . _ ~>
```

```bash
systemctl daemon-reload
systemctl enable --now power-server
journalctl -u power-server -f
```

- `--allow` – принимать запросы только с адреса контроллера; ключ защищает команду выключения.
- `--wol-interface` – физическая сетевая карта (не мост `vmbr0`): перед выключением агент
  включает на ней WOL (`ethtool -s eno1 wol g`). WOL также должен быть включён в BIOS/UEFI.
- `--dry-run` – команда выключения только пишется в журнал. Убедитесь, что контроллер доходит до
  агента, затем уберите `--dry-run` и выполните `systemctl restart power-server`.
- Если включён firewall Proxmox, разрешите входящий TCP 8080 с адреса контроллера.

Настройки контроллера для Proxmox: IP и порт 8080 сервера, MAC его сетевой карты, путь проверки
`/ping`, путь выключения `/poweroff?key=<ключ>`.

Без сервера контроллер можно проверить эмулятором на Windows: `server/test_server.bat`
(`--help` – режимы, например сервер, который не выключается или не просыпается от WOL).
